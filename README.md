# AI 游戏陪玩（屏幕共享 + 悬浮对话框）

实时看你的屏幕 → 用视觉模型读画面 → 在置顶悬浮窗里跟你聊怎么打。
首个适配游戏：**《杀戮尖塔》Slay the Spire**（回合制，最吃“看图给建议”这个场景）。

---

## 1. 怎么启动

**双击 `启动-ai陪玩.bat`** 就行。

也可以命令行：

```powershell
cd C:\Users\dqy20\Desktop\dsh工作区\休闲\game-copilot
python main.py
```

启动后屏幕右上角会出现一个悬浮窗，标题栏右侧有 `—`（收起）和 `✕`（隐藏）。

## 2. 两种工作模式（重点，解决"点一下游戏就掉后台"）

| 模式 | 行为 | 切换 |
|---|---|---|
| **🔒 只读模式（默认）** | 窗口在**操作系统层面**就不接收鼠标、不激活，所以点它永远不会把游戏顶到后台。代价：按钮点不动、不能打字 | 按 **F7** |
| **🔓 交互模式** | 可以点按钮、点输入框打字。代价：点窗口时游戏会掉到后台 | 按 **F7** |

推荐玩法：**平时保持只读模式**，用 F8 看屏幕（或 F10 连续陪玩），AI 的建议实时刷在悬浮窗里，全程不用离开游戏；
要打字追问时按一下 F7 切到交互模式，问完再切回来。

> 为什么不能既要又要：Windows 的"不激活"是操作系统级别的。窗口既然不被激活，
> 键盘焦点就永远进不去，所以"能打字"和"不抢焦点"天生互斥，切换是唯一的解法。

## 3. 热键

程序启动时会在悬浮窗第一行告诉你**实际生效的按键**（被占用会自动换备选键）。

| 热键 | 作用 | 备选键 |
|---|---|---|
| **F8** | 让我看一眼屏幕并给建议（最常用，只读模式下也能用） | Ctrl+Alt+Z |
| **F7** | 切换 只读 / 交互模式 | Ctrl+Alt+M |
| **F9** | 显示 / 隐藏悬浮窗 | Ctrl+Alt+X |
| **F10** | 连续陪玩开关（每 12 秒自动看一次） | Ctrl+Alt+C |
| **F11** | 鼠标穿透（点击直接落到游戏上） | Ctrl+Alt+V |
| **F12** | 清空对话上下文 ⚠️ 本机 F12 被别的软件占用了，会自动换成 Ctrl+Alt+B | Ctrl+Alt+B |

直接在输入框里打字 + 回车 = “看一眼屏幕 + 回答我的问题”（文字和画面会一起发过去）。

技术说明：热键用的是 Windows 原生 `RegisterHotKey`，**不需要管理员权限**，全屏游戏里也能收到。
（早期版本用的 keyboard 库钩子在你机器的全屏游戏下完全收不到事件，已弃用。）

> 再开一份程序会弹出提示并自动退出——两份实例会互相抢热键，看起来就像"热键失灵、消息丢失"。

## 4. 游戏该怎么设置（重要）

- 你的游戏是**无边框全屏**，实测悬浮窗能正常盖在上面，所以**不用改显示模式**。
- 如果你哪天换成「独占全屏（Exclusive Fullscreen）」，置顶窗口会被游戏盖住，抓屏也可能黑屏，那就改回窗口化。
- 点进悬浮窗输入框打字需要先按 **F7** 切到交互模式（原因见上一节），游戏会短暂失去键盘焦点。

## 5. 花费与延迟（实测数据）

在 2560×1600 / 150% 缩放的屏幕上实测：

| 项目 | 数值 |
|---|---|
| 抓屏 + 压缩 | 0.3 ~ 0.5 秒（2560×1600 → 1280×800 JPEG） |
| 首字延迟 | 0.5 ~ 1.4 秒 |
| 完整回答 | 2 ~ 12 秒（取决于画面复杂度和要不要深入推理） |
| 单次消耗 | 约 **1000 ~ 2800 tokens**（其中约一半是模型的“思考”） |

省钱技巧（改 `tray_config.py`）：

- `max_tokens` 调小、`reasoning_effort` 改成 `"none"` → 更快更省
- 别开 F10 连续模式挂机，用 F8 按需看
- `SCREEN["max_side"]` 从 1280 降到 1024（清晰度略降，token 省一截）
- `BEHAVIOR["history_keep_images"]` 保持 `1`（历史里塞多张图会成倍变贵）

## 6. 它知道你的卡组（选牌/商店才有好建议）

看图只能认出「这一手有什么牌」，认不出「你整套卡组 + 遗物是什么」，
所以一到选牌、商店、篝火升级界面，光靠截图给的建议会偏。

程序会自己去游戏的跑局记录里读：**角色、进阶等级、打到第几层、完整卡组、全部遗物**，
在一条对话的第一句里带进上下文（之后不再重复发，省 token）。启动时悬浮窗会告诉你读到没有。

如果读到的是**上一局**的数据（游戏只在跑局结束时写文件），提示词里会明确标注「这是上一次的，别当当前状态」，
你也可以在程序目录建一个 `deck.txt`，自己粘一份当前卡组，优先级最高、最准：

```
角色：铁甲战士 进阶3
卡组：打击×4、防御×4、痛击、全身撞击+、壁垒+、金属化+…
遗物：燃烧之血、金刚杵、双节棍…
```

手动验证：`python runinfo.py`（会打印当前读到的卡组资料）。

## 7. 想换游戏 / 改性格

- **换游戏**：改 `prompts.py` 里的 `SLAY_THE_SPIRE`，或加一个新条目并在 `main.py` 里改
  `self.system_prompt = prompts.get("你的键名")`。
- **改风格/长度**：改 `BASE_ROLE`（“150 字以内”这种话就在这里）。
- **改外观**：`tray_config.py` 里的 `WINDOW`（宽高、透明度、字号、配色）。
- **改热键**：`tray_config.py` 里的 `HOTKEYS`。

## 8. 出问题时

| 现象 | 原因 / 处理 |
|---|---|
| 悬浮窗里出现红色的“启动自检没过” | Key 无效 / 余额不足 / 网络不通，按提示先解决 |
| “只输出了思考、没输出答案” | `max_tokens` 给少了，调到 3500 或 `reasoning_effort: "none"` |
| 抓到的画面是黑的 | 游戏是**独占全屏**，改成窗口化 / 无边框窗口 |
| 悬浮窗被游戏盖住 | 同上，独占全屏会盖住所有置顶窗口 |
| 热键没反应 | 看悬浮窗第一行的“实际生效的热键”；被占用会自动换备选键，日志里也有记录 |
| 按 F8 没反应、消息也不见了 | 看 `copilot.log` 有没有「热键触发：analyze」；有触发但没动作就是投递出了问题，把日志发我 |
| 回答里出现了“上一张截图” | 上下文里只有 1 张历史图，属正常（省 token 的设计） |
| 想彻底重来 | 按 F12 清空上下文，或关掉重开 |

日志在 `copilot.log`，报错时把它发我。

## 9. 自检工具（不用开游戏就能验证）

```powershell
python screen.py                    # 抓屏自检，会存一张 _selftest_shot.jpg
python llm.py                       # 抓屏 + 调模型 + 流式输出，全链路自检
python runinfo.py                   # 看能不能读到你的卡组/遗物
python test_headless.py             # 无头跑一遍完整流程（不开 GUI）
python test_hotkeys.py              # 验证热键注册 + 回调链路（不需要真的按键）
python test_f8_flow.py              # 验证「按 F8 → 看屏 → 回答」+ 消息不丢
python test_vision.py 图片.jpg      # 拿指定截图测「读牌」准不准
python test_live_game.py            # 自动开游戏 → 抓真实画面 → 分析 → 存档截图
python test_synthetic.py            # 自造一张中文界面图，量化模型读数准确率
```

### 实测结论（2560×1600 / 150% 缩放屏）

- 合成中文界面测试：**21 个字段里读对 18 个** —— 能量、血量、格挡、金币、层数、
  5 张手牌的名字和费用、两个敌人的血量和名字、遗物名，全部正确。
- 读不准的是**意图上的小号伤害数字**（图中 11 和 7）。模型的处理是对的：它说「看不清」而不是编一个数。
  为了这件事，提示词里已经要求它读不准就直接问你，按你念的数字算。
- 真实游戏实测：自动启动《杀戮尖塔》，抓屏拿到的是正常画面（不是黑屏），
  模型正确识别出中文主菜单的六个选项。

| 文件 | 作用 |
|---|---|
| `main.py` | 主程序：托盘、热键、任务调度、上下文管理 |
